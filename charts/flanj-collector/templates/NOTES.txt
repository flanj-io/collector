1. Point your application at the fronts. This goes on YOUR workload's
   container — it is the application that sends, not the collector that
   receives, and not your shell:
{{- $svc := .Values.service.front.fixedName | default (include "flanj-collector.front.fullname" .) }}

     env:
       - name: FLANJ_OTLP_ENDPOINT
         value: http://{{ $svc }}.{{ .Release.Namespace }}:{{ int .Values.service.front.port }}/v1/logs
       - name: NODE_OPTIONS
         value: "--require @flanj/sdk/register"

   The second variable is the SDK preload: without it the app sends nothing,
   because nothing loads the SDK. A Python app needs no NODE_OPTIONS —
   `import flanj.register` as its first line is the preload.
{{ if .Values.service.front.fixedName }}
   That address is the same for every install that used the documented command,
   because `service.front.fixedName` gives the front Service a name that does
   not move with the release name.
{{- else }}
   `service.front.fixedName` is empty, so this is the release-scoped Service
   name — it changes if you rename the release, and it is not the address the
   documentation prints.
{{- end }}
{{- if .Values.endpointConfigMap.enabled }}
   The same value is in ConfigMap/flanj-endpoint (key FLANJ_OTLP_ENDPOINT) in
   {{ .Release.Namespace }}{{ with .Values.endpointConfigMap.namespaces }} and in {{ join ", " . }}{{ end }}, if you would rather write
   `envFrom: [{configMapRef: {name: flanj-endpoint}}]`. A pod can only
   reference a ConfigMap in its OWN namespace: add yours to
   endpointConfigMap.namespaces. envFrom replaces only FLANJ_OTLP_ENDPOINT:
   a Node workload still needs `env: [{name: NODE_OPTIONS, value:
   "--require @flanj/sdk/register"}]` beside it, or the SDK never loads and
   nothing is captured. Python does not need it.
{{- end }}

2. Open the UI. It binds container loopback on the STORE pod by design — the
   collector is outbound-only and nothing it serves is reachable off-host:

     kubectl -n {{ .Release.Namespace }} port-forward {{ if eq .Values.store.backend "sqlite" }}sts/{{ include "flanj-collector.store.fullname" . }}{{ else }}deploy/{{ include "flanj-collector.store.fullname" . }}{{ end }} 5335:5335

   then http://localhost:5335 (health: /api/health). Check the port is free
   first: lsof -nP -iTCP:5335 -sTCP:LISTEN (macOS/Linux; no output = free).
   If something holds it, kubectl does not fail: it binds [::1] only, prints
   a normal "Forwarding from [::1]:5335" line, and the UI address then answers
   from whatever holds the IPv4 port. Forward 15335:5335 and open
   http://localhost:15335 instead. localhost and 127.0.0.1 both reach the UI
   only when the port-forward bound both. An upgrade that replaces the store
   pod ends the port-forward; run it again.

3. CHECK A FRONT'S LOGS, not just that its pods are Ready. The two roles fail
   differently on purpose: the store pod refuses to start without a contract
   token, a front with the wrong one starts, gets 401, and quietly detects no
   REST drift at all. This chart gives both roles the same Secret key, so the
   only way to see this is an existingSecret whose value changed under you.
   Naming one Deployment only follows one of its pods — add --all-pods (or
   select on the label) so a 401 on the other front is not missed:

     kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "flanj-collector.front.fullname" . }} --all-pods | grep -i 'contract refresh'

   Two refresh failures are expected within the first minute, in either
   order: the store Service not yet resolvable (`no such host`) or not yet
   Ready (`context deadline exceeded`), about 15-35 seconds after the pod
   starts. There is no success line: silence after them is the healthy
   result. A 401 is never expected.

4. controlPlane.baseUrl is empty, so this deployment is fully local: it
   captures, redacts and detects drift, and it cannot create thread links.
   Restore it to Connect — the default, https://app.flanj.io, is the hosted
   control plane, and controlPlane.publicUrl is the same address there.
{{- else }}
4. Connect in the UI (Settings → Connect) to create thread links: a collector
   name and a contact email, no token — the contact's confirmation click is
   the consent (controlPlane.deployToken is optional). Until then nothing is
   sent to {{ .Values.controlPlane.baseUrl }}. The Connected pill's dashboard
   door is minted from
   {{ if .Values.controlPlane.publicUrl }}controlPlane.publicUrl ({{ .Values.controlPlane.publicUrl }}){{ else }}controlPlane.baseUrl, which is not set for a browser: an in-cluster
   address a laptop cannot resolve leaves the pill a Settings button rather
   than a dead link. Set controlPlane.publicUrl if the two differ{{ end }}.
{{- end }}
